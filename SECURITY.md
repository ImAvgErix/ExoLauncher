# Exo Launcher security model

## Trust boundaries

- The unpackaged WinUI 3 desktop process runs as the signed-in Windows user (`asInvoker`). Store backends remain vendor processes.
- The UI is React in WebView2, served from the bundled `app.exo-launcher.local` virtual host. `WebHostBridge` exposes bounded operations to that shell page only; music players and store sign-in pages run in other WebView2 profiles with no bridge. The Discord Shop's card form is its own page on its own origin (`pay.exo-launcher.local`), the only page that loads Stripe, so card fields never share Exo's page. Store tokens, the Discord sign-in, saved keys and filesystem paths stay in native code.
- Exo has no account and no server of its own. The exo-id account service earlier versions signed in to is not contacted, and its client and source are gone; the only account state Exo kept on the PC (`auth.bin`, `online-cache`) is deleted locally on start by `LegacyProfileDataCleanup`.
- Dependency installs and purchases require user action. Exo does not silently force system changes.
- Exo serves no OpenMouse loopback API (port 17846 is the OpenMouse Bridge app's alone). The Devices room is Exo Mouse, a separate AGPL program in an iframe on its own origin (`mouse.exo-launcher.local`) with its own CSP (`default-src 'none'`, `connect-src 'none'`, `frame-src 'none'`). It reaches Exo only by postMessage, and Exo's page answers only messages from that frame on its own origin, and only an allowlist: the HID calls (`hid.list`, `hid.open`, `hid.close`, `hid.sendReport`, `hid.sendFeatureReport`, `hid.receiveFeatureReport`, `hid.receiveInputReport`), one read of the installed games (id, title and Exo's own cached cover thumbnail, for linking mouse profiles to games), reading and writing its own profiles file (one JSON object, at most 512 KB, written atomically), and reading Exo's text size, motion and Appearance. One-way posts are capped: a notice at one 160-character line, the mouse's name at 60 characters with its battery, its profile's name at 40. Every other method is dropped, and the host bridge refuses any message whose source is under `/mouse/` (`WebViewTrustPolicy.IsTrustedBridgeSource`), so the frame cannot skip the allowlist by posting to the host itself. Devices are named by an opaque hashed key, never a path. `HidService` opens every collection shared, never exclusive. Of the collections Windows keeps for itself, it skips keyboards, and opens a mouse or pointer collection with no access, for its feature reports only (where Razer keeps its settings), never its movement. No vendor software or driver is installed.

- Exo's own process never captures the screen (BannedSymbols.txt, BannedNativeImportsTests). Capture lives only in Exo Capture (`capture/`, GPL-3.0-or-later), a separate program Exo starts from `addons\capture`. Exo talks to it only over that process's standard input and output, anonymous pipes the two processes alone hold: no loopback port (the hole Spotify's debugging port had) and no named pipe another program could open. It captures with Windows.Graphics.Capture and process loopback audio. Only when Windows gets no picture from a game (exclusive full screen) does it load OBS Studio's signed game capture hook into that game, through OBS's own anti-cheat compatible injection; never into Riot games, while FACEIT or ESEA runs, or into a Store app. It acts on files (trim, export, thumbnails, copy, image save) only inside the captures folder, and Exo checks every capture id against that folder before passing a path.
- Exo Shaders (`addons\shaders`, GPL-3.0-or-later) is a separate engine Exo starts hidden at below-normal priority and talks to the same way, over its standard input and output only; no part of it runs in Exo's process.

## Data handling

- Application logs redact authorization/session material, passwords, email, provider/store tokens, store-native ids, friend-id lists, and account/user ids.
- Optional keys, the Riot ID and the Discord sign-in (`DiscordToken`, sent only to Discord's own hosts, never to the UI) are current-user DPAPI blobs (`ExoDpapi`) whose file DACL `SecretFileAcl` best-effort restricts to the current user and SYSTEM. Same-user malware can still read them; DPAPI is not an application sandbox.
- Spotify, which Exo hosts, is driven over a private DevTools pipe (`--remote-debugging-pipe`, `SpotifyDevTools`), never a port: Exo holds both ends and Spotify inherits only those two handles, so no other program can find or drive Spotify's signed-in page. In 3.5.0 and earlier it was a random loopback port, which another program running as the user could read from Spotify's command line and use.
- Logs also redact secrets logged with no label: three-part tokens (JWT, Discord) and long mixed-case runs (OAuth access tokens). Single-case hex such as download hashes stays readable.

## Anti-cheat safe (always)

- No kernel hacks or bypass for Vanguard, EAC, BattlEye, or Steam DRM.
- Cleanup after launch only soft-closes store **UI** processes — never anti-cheat. `ProcessTermination.Kill` refuses Vanguard, EAC, BattlEye, FACEIT, PunkBuster, XIGNCODE3, GameGuard, ACE and any game's `_BE`/`_EAC` launcher, at the root and in every process of a tree, and reports a refused close as not ended.
- Optional upscaler updates for DLSS / FSR / XeSS replace only files the game already ships, and keep the shipped original (`.dlsss`, `.exo-bak`) for a byte-checked Restore. Every file is an official vendor build: pinned by SHA-256 in `DlssSwapService.Releases.cs`, or, from DLSS Swapper's list or a vendor's newer GitHub release (`DlssSwapService.Catalog.cs`, `DlssSwapService.VendorWatch.cs`), matched to the listed size and MD5 or GitHub's size and git blob hash, then to the vendor's Authenticode signature, identity, exports, x64 and exact version, and pinned by the SHA-256 it was verified at. Games with anti-cheat (by store, title, or any anti-cheat file or folder in the install) are not modified unless the user allowed it for that game after a confirmation that names the anti-cheat and the ban risk; the consent is stored per game, tied to that anti-cheat, re-checked under the write lock and logged with each write. Riot games and Riot Vanguard are never modified, with no override. They are user-requested file swaps, not silent patches.

## Red-team attacks

Attacks on the bridge, URLs, files, downloads and the local surface are kept as rerunnable proofs: `security/attacks/bridge/` (see each script's header), `security/attacks/files/Run-Attacks.ps1` (xUnit, in `ExoLauncher.Tests`) and `security/attacks/local/run-all.ps1`. Each found hole is fixed with a test that fails when the fix is turned off.

## Reporting

Open a GitHub issue on [UhhErix/ExoLauncher](https://github.com/UhhErix/ExoLauncher) for security-relevant bugs. Do not include tokens, account exports, store ids, local paths, or other personal data in a report. Bypass requests will be closed.
