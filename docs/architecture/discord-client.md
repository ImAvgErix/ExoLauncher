# Exo's own Discord client

The Discord room is Exo's client (`ExoLauncher/Services/DiscordClient/`, `ui/src/components/discord/`); Exo never hosts, installs or patches the Discord desktop app. It covers text (servers, channels, threads, forums, DMs, messages, reactions, pins, polls, search, inbox), server settings and moderation, Discord's settings, calls, cameras and Go Live. Video and Go Live: `discord-video.md`.

## Rules it keeps

- Signs in only by QR code (Discord's phone app confirms); Exo never takes a password.
- The token is DPAPI-wrapped in `discord-client.bin` (current user only, `DiscordToken`), sent only to Discord's own hosts, never to the UI, never logged. Sign out deletes the file and calls `POST /auth/logout`.
- Acts only on what the user does in the room. No automation, nothing on a timer for anyone else, no captcha solving: a captcha reply becomes a plain line telling the user to use the Discord app once.
- Channel visibility is computed in the host (`DiscordCache`) with Discord's permission rules: base from @everyone plus the user's roles, Administrator or owner sees all, then the channel's @everyone, role and member overwrites. A channel without View Channel never reaches the UI, nor do its messages or typing (`DiscordCacheTests`). No deleted-message logging: a delete removes the message.
- Messages are held only in memory (the page keeps the newest of the last 30 conversations, `messageCache.ts`); nothing is written to disk.
- No Nitro entitlement spoofing.

## Protocol (as Discord's web client)

- Identity: Chrome on Windows (`DiscordRest.Properties`), the User-Agent from the installed WebView2's major version, and `client_build_number` read from discord.com's own scripts at start (fallback constant).
- QR sign-in (`DiscordRemoteAuth`): `wss://remote-auth-gateway.discord.gg/?v=2`. Exo sends `init` with an RSA-2048 SPKI key, answers `nonce_proof` with base64url(SHA-256(decrypted nonce)), shows `https://discord.com/ra/<fingerprint>`, then trades the `pending_login` ticket at `POST /users/@me/remote-auth/login` for `encrypted_token` (RSA-OAEP SHA-256). The key exists only for that sign-in.
- Gateway (`DiscordSession`): `wss://gateway.discord.gg/?encoding=json&v=9`, no compression, capabilities `DEDUPE_USER_OBJECTS` (1<<4) so READY carries `users`, `recipient_ids` and `merged_members`. Heartbeat, zombie detection (no ACK means reconnect), resume through `resume_gateway_url`, a fresh identify after op 9 with `d: false` or close 4007/4009, sign-out on 4004. Opening a server channel sends op 37 (bulk guild subscriptions) for live messages in large servers; if the gateway answers with 4002 right after, Exo stops sending it.
- REST (`DiscordRest`): `discord.com/api/v9` for messages (50 per page), send (`nonce` snowflake, `message_reference` for replies), edit, delete, ack (`last_viewed` as days since 2015-01-01) and typing. 429s under 10 s are waited out up to twice.
- Notifications (`DiscordCache.Notifies`, after the web client's `shouldNotify`): never your own message, a `SUPPRESS_NOTIFICATIONS` (@silent) one, a blocked person's, a message request's, or anything under Do Not Disturb, and each message once. DMs notify of every message unless muted; servers follow mutes (server, category, channel, a thread's channel), opt-in channels and the resolved level, with a voice channel's chat at All Messages only while in that call. `DiscordNotifier.Route`: nothing for the conversation on screen while Exo is in front, nothing while a game runs with Game focus on; only the sound under Streamer Mode's Disable notifications or with desktop notifications off; else Exo's banner (`discord.notify`) while in front, a Windows notification (tag = message id, group = channel id, the avatar as a local PNG) in the background. MESSAGE_ACK, a local ack, opening the conversation and Exo coming to the front clear the channel (`discord.notifyClear` and `RemoveByGroupAsync`), as Discord does on MESSAGE_ACK, CHANNEL_SELECT and WINDOW_FOCUS; MESSAGE_DELETE removes that one message's.

## Voice

- Joining (`DiscordSession.Voice.cs`): main gateway op 4 `{guild_id, channel_id, self_mute, self_deaf, self_video, flags: 2}`; Discord answers `VOICE_STATE_UPDATE` (this session's voice `session_id`) and `VOICE_SERVER_UPDATE` (`token`, `endpoint`; for a DM call `channel_id` stands in for the guild). DM calls ring with `POST /channels/{id}/call/ring`; `CALL_CREATE` or `CALL_UPDATE` ringing this user notifies.
- Voice gateway v8 (`Voice/VoiceConnection.cs`): identify with `max_dave_protocol_version` from libdave, heartbeats `{t, seq_ack}`, resume `{server_id, session_id, token, seq_ack}`, binary DAVE messages. Closes 4004, 4011, 4014, 4016, 4017, 4021 and 4022 end the call; 4006/4009 start over.
- UDP (`Voice/VoiceTransport.cs`): IP discovery, then RTP (payload type 120, Opus 48 kHz stereo, 20 ms) under `aead_aes256_gcm_rtpsize` (preferred) or `aead_xchacha20_poly1305_rtpsize`. The RTP header and extension preamble are the additional data; a big-endian 32-bit counter is appended as the nonce.
- DAVE (`Voice/DaveSession.cs`): a C# port of libdave's reference `DaveSessionManager` over its C API (`dave.dll`, `Voice/VoiceNative.cs`); only users announced by op 11 are accepted into the MLS group.
- Sound (`Voice/VoiceAudio.cs`): shared-mode WASAPI on the chosen devices, else Windows' default microphone and speakers (`AudioDevices`, the console role, as Discord picks them), event driven, Windows converting to 48 kHz stereo float. Microphone sound more than 40 ms later than that mic usually is gets dropped, not sent late. Five Opus silence frames before speaking stops. Each speaker is evened out toward one speaking level (`VoiceLeveling`, Even Out Voices) and gets a jitter buffer that starts at 60 ms and drops past 200 ms. `Voice/LiveAudio.cs` keeps Exo fit for real time while any live sound runs, and each audio thread joins MMCSS as it starts (`MmcssTask`).
- Microphone chain (`Voice/VoiceChain.cs`, the same for a call, Voice Check and Voice Tune): echo cancellation on speakers first (`Voice/EchoCanceller.cs`, WebRTC AEC3 in `exo_apm.dll`), then the low cut and knock detector, noise suppression, Voice Focus or the level gate (`Voice/VoiceFocus.cs`, `VoiceGate`), gain control on the cleaned voice (`SpeechLeveler`), the gate's release fade, the compressor (`Compressor`), then Clip Guard. Profiles: `Voice/VoiceInput.cs`; per-mic tuning: `Voice/VoiceTune.cs`.
- Noise suppression (`Voice/NoiseSuppressor.cs`): DeepFilterNet 3's low-latency model through its own C interface, Exo's build of v0.5.6 with three entry points added (`voice/deepfilter/exo-capi.rs`), each 20 ms frame cleaned as two 10 ms hops on the caller's thread. Fetched once from Exo's GitHub release (pinned size and SHA-256) when the Discord client starts. Noise Suppression for Others gives each voice heard its own instance (`Voice/InboundCleaner.cs`).
- Natives: `voice\build.ps1` builds `dave.dll` (libdave pinned, mlspp and OpenSSL 3 static, Visual Studio's vcpkg in manifest mode), `opus.dll`, `exo_apm.dll` (webrtc-audio-processing 2.1) and the DeepFilterNet library (needs Rust), into `voice\out`.

## Checked

- The E2E `discord` suite (`tools/e2e/suites/discord.mjs`, test place only) checks sign-in, the test channel, a message sent, reacted to and deleted, invite links, server pages, settings and profiles. xUnit covers the cache, notifications, gateway limits, voice and Go Live logic (`ExoLauncher.Tests/Discord*Tests.cs`, `GoLiveTests`, `Voice*Tests`). Calls are tried by hand in the test place.
